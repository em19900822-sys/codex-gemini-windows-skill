# Gemini 长对话约两分钟后断开

## 先区分超时与代理故障

适用于 `stream disconnected before completion: The provider connection failed.`，且短新对话正常、长旧对话重复在相近时长失败的情况。这条通用错误本身不能证明网络断开或账号失效。

先收集最小证据：

1. 当前系统代理、端口监听者与两段后台实际继承的代理地址是否一致。
2. 同一模型的新临时对话是否正常返回；测试需沿用现有账号并说明少量额度消耗。
3. 失败请求的耗时、错误类别及历史消息数量，只输出计数，不复制聊天正文。
4. 目标电脑安装的中转版本、实际提供商类型和传输等待时间。不同版本不能照搬字段。

如果代理地址过期或 Google 授权连接失败，先走 [代理端口恢复](proxy-port-recovery.md)。只有连接正常、失败时长反复接近传输上限时，才考虑以下调整。长历史只是线索，不足以断言超出模型上下文容量。

## 最小调整

本案例的 Gemini 使用 `google-antigravity` 提供商、`openai_chat` 路由，经过本机 Antigravity。已检查的中转实现中，`OpenAICompatibleTransport` 默认等待时间为 120 秒，可由提供商的正数 `timeout` 覆盖。它是 HTTP 客户端等待设置，不保证整个任务五分钟内完成。

执行前，在目标电脑检查 `byok` 的配置规范化及安全存储接口、`provider_timeout` 与服务端请求路径，确认该版本确实支持此字段，并发现实际配置位置。

- 将现有加密提供商文件备份到本机私有目录；不可放进 Skill、公开仓库或发布压缩包。
- 使用包内受支持的安全配置读取和更新接口。该案例使用 `byok.load_provider_config_read_only` 与 `byok.update_secure_json_file`，配合 `get_providers_json_path`、`default_provider_config`、`normalize_provider_config`；先确认当前版本签名。不要把扩展名为 JSON 的加密文件当明文重写。
- 在更新回调中仅将目标提供商的 `timeout` 调整为 `300.0`。保留认证、模型完整列表、GPT、其他提供商及所有其他字段。已有值达到或超过 300 秒时不重复调整，也不自动继续加大。
- 安全读取回写结果，并比较修改前后结构，确认只有这一字段变化。用实际路由合并后的提供商检查有效超时为 300 秒，不能只检查文件存在。
- 本案例的服务端逐请求读取配置，因此无需重启。其他版本先验证是否动态读取，再决定是否只重载对应后台；不要终止 Codex 桌面。

不将 300 秒写成所有新电脑的强制默认值，不修改整个系统代理，不重装、不重新登录，也不无限提高等待时间。

## 验证、停止与回退

1. 运行 `scripts/probe_app_server.py`，传目标电脑实际 Codex 路径、模型 ID 和 `--expected-provider local-unified`，验证正常回复。临时测试的 `--timeout` 是测试进程自己的期限，与提供商等待设置不同；短测试不能验收超过两分钟的请求。
2. 用户在原长对话重新发送一次，才是该故障的最终验收。未经明确授权，不向另一个已有任务自动发送消息。
3. 原对话若仍失败，记录新耗时和上游脱敏错误，检查上游是否持续无输出；停止重复延长超时。不要以短对话成功宣称原长对话已修复。
4. 回退时通过相同安全接口恢复这一字段的原值；原先不存在则只移除该字段。若期间有其他配置变化，不用整份旧备份覆盖它们。

## 已有验证记录与边界

2026-09-30 的一次本机故障：旧对话约 352 条历史消息，反复在约 123 秒失败；相同模型的短临时对话约 18 秒完成，后台继承的代理地址与系统代理一致。这支持“默认等待上限过短”的判断，但没有证明上游变慢的具体原因。

当时仅将提供商等待时间从默认 120 秒调整到 300 秒，确认其他配置未变化；Gemini 3.8 Flash 的临时 Codex 后台测试完成并返回预期文本。**原长对话的桌面恢复尚未取得确认。**

2026-10-11 同步 Skill 时，只读复查本机配置和传输选值，仍为 300 秒；本次没有额外模型调用，不据此宣称当前所有对话正常。公开记录不附账号、配置备份或聊天日志。
